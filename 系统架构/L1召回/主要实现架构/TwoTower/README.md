# Two-Tower Retrieval

## 核心思路

双塔分别编码用户/请求和物品：$u=f(x_u)$，$v=g(x_i)$，匹配分数为 $s(u,i)=u^\top v$。物品向量可离线计算并建立 ANN 索引，请求到来时只需在线计算用户向量。

## 数据构造

- 正例：请求与归因后的点击、有效观看、收藏或购买物品组成配对。
- 随机负例：成本低但通常过易。
- 批内负例：同批其他正例物品作为负例，计算利用率高。
- 难负例：从旧模型近邻或曝光未点中选择，需警惕假负例和选择偏差。
- 采样不均匀时，应按采样概率修正 logit 或进行重要性加权。

## 典型结构与损失

示例使用两套 Embedding + MLP，并对输出做 L2 归一化。一个批次的用户向量与物品向量形成 $B\times B$ 分数矩阵，对角线为正例，其余为批内负例：

$$
\mathcal{L}=-\frac{1}{B}\sum_b\log\frac{\exp(s_{bb}/\tau)}{\sum_j\exp(s_{bj}/\tau)}
$$

## 文件与运行

- [model.py](./model.py)：双塔编码器、相似度矩阵与批内对比损失。
- [train.py](./train.py)：使用合成的用户-物品偏好对训练并输出 Top-K。

在安装 PyTorch 后，于本目录执行 `python train.py`。

## 线上部署

离线用物品塔导出全量向量，在线用用户塔生成 query，二者必须共享模型版本、维度、归一化方式和距离函数。ANN 建库与更新见[ANN 与索引](../../共享基础设施/ANN与索引.md)。

## 局限与扩展

塔间交互仅发生在向量内积处，表达能力弱于交叉编码器。后续可扩展多兴趣用户向量、序列编码器、多模态物品塔、跨批负例和知识蒸馏。
