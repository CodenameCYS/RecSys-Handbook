# Generative Retrieval

## 核心思路

生成式召回将候选生成改写为序列生成：给定用户行为序列，模型生成下一个物品的原始 ID 或离散语义 ID。TIGER、HSTU 和 OneRec 等工作探索了语义标识、规模化序列建模以及召回排序统一。

## 数据构造

- 输入：按时间排序的用户交互及可选上下文、多模态内容。
- 标签：下一个物品 ID，或由残差量化器产生的多级语义代码。
- 自回归交叉熵不一定显式采负例，但候选对齐和偏好优化仍可能使用拒绝样本与难负例。
- 语义 ID 需要记录码本训练、冲突消解、层级结构和新品分配策略。

## 典型结构与损失

示例使用物品 Embedding、GRU 序列编码器和全物品分类头预测下一个物品：

$$
\mathcal{L}_{gen}=-\sum_t\log p(i_t\mid i_{<t})
$$

这是理解生成式目标的最小基线；生产级语义 ID 模型通常使用 Transformer、分层代码和合法 ID 约束解码。

## 文件与运行

- [model.py](./model.py)：GRU 自回归物品生成模型。
- [train.py](./train.py)：构造序列样本、训练并贪心生成候选。

安装 PyTorch 后执行 `python train.py`。

## 部署方式

可使用 beam search、合法 ID trie 和库存约束解码。服务必须处理非法/重复 ID、beam 与时延预算、新品接入、缓存、超时降级及传统通道融合。

## 局限与扩展

关键挑战是全库更新、语义 ID 稳定性、解码成本、热门偏差和与强 ANN 基线的公平比较。后续应补充语义 ID 量化、受约束 beam search 和 OneRec 式偏好对齐。
