# 曝光公平与长尾扶持

曝光公平关注不同主体获得的展示机会是否与其价值、资格或既定政策一致；长尾扶持关注曝光是否过度集中在头部。二者都需要跨请求累计统计、稳定的群体定义和业务护栏，不能仅靠单次列表“平均分配”判断成效。

本页讨论的是可展示候选之间的软权衡。合规、安全、库存、强频控和实体排他性必须先由[基础规则与约束](../../基础规则与约束/README.md)完成；本策略只能影响后续[列表重排](../../列表重排/README.md)或[约束优化与编排](../../约束优化与编排/README.md)中的可行候选选择。

## 1. 对象、事件与统计口径

| 概念 | 推荐定义 | 常见混淆 |
| --- | --- | --- |
| 主体/组 $g$ | 作者、商家、内容簇、类目或经审批的供给分层 | 同一候选可多组归属，须定义归因权重或主组。 |
| 展示机会 | 服务端返回并交给客户端渲染的列表项 | 不等于用户真实看见。 |
| 真实曝光 | 客户端在可见条件满足后确认的事件 | 必须包含请求、位置和幂等键。 |
| 价值 | L2 校准效用、质量门槛或经审核的供给资格 | 不能用未校准分数直接推导“应得曝光”。 |
| 统计窗口 | 滑动窗、自然窗或指数衰减累计 | 窗口边界与迟到事件会改变偏差判断。 |

最小状态契约应包括 `group_id`、`weighted_exposure`、`event_watermark`、`snapshot_at`、`target_share`、`group_version` 和 `policy_version`。请求日志还应保存命中组、原始效用、调整值、位置权重、所用快照与回退模式。

## 2. 度量与受限调整

给定窗口内加权曝光 $E_g$，实际份额、集中度和长尾覆盖可写为：

$$
q_g=\frac{E_g}{\sum_hE_h},
\qquad
HHI=\sum_gq_g^2,
\qquad
coverage_{tail}=\frac{|\{g\in\mathcal{T}:E_g>0\}|}{|\mathcal{T}|}.
$$

HHI 越高，曝光越集中；但它不说明集中是否合理，因此必须同时查看组质量、用户效用和目标份额。对于已审批目标 $\pi_g$，可按累计短缺加入截断调整：

$$
score_i'=u_i+\operatorname{clip}\left(
\eta(\pi_{g(i)}-q_{g(i)}),-b_{max},b_{max}
\right).
$$

调整上限 $b_{max}$ 是用户保护栏，目标份额不等于对每个请求的强制平均分配。若某组当次没有合格候选或候选效用明显不足，应记录未满足的软目标，不应引入不合格内容。

```powershell
& c:/Users/CodenameCYS/anaconda3/envs/py3.12/python.exe example.py
```

示例故意不处理曝光回写、事件去重、多组归因或基础规则；这些能力属于生产状态链路，不能由一次排序替代。

## 3. 请求时流程与状态语义

```mermaid
flowchart LR
	A[基础规则后的候选] --> B[提取主体/长尾分组]
	B --> C[去重并批量读取曝光快照]
	C --> D[计算份额偏差与截断调整]
	D --> E[重排或联合编排]
	E --> F[记录选择与调整原因]
	F --> G[客户端真实曝光确认]
	G --> H[幂等聚合累计状态]
```

服务端生成的列表只记录候选的**预期**位置权重；累计 $E_g$ 应以客户端确认事件或经审批的校正估计更新。迟到、重复和撤回事件需要 watermark、幂等键与重放策略。状态未知、快照过期或组映射缺失时，不能推断该组“欠曝”；进入缓存、neutral 或基线模式必须写入日志。

## 4. 复杂度、空间与预算

令 $N$ 为候选数、$R$ 为每候选分组数、$G_a$ 为请求激活分组数、$B$ 为统计窗口的桶数。利用批量快照，本地调整成本为 $O(NR)$，请求工作区为 $O(G_a)$；候选多组归属和稀疏映射会决定实际常数。

累计状态若用时间桶，空间为 $O(GB)$；若用指数衰减累计，通常为 $O(G)$，但重放与审计粒度较弱。请求路径应只读取去重后的 $G_a$ 个组，不对每个候选发起状态 RPC；状态回写应异步幂等，避免让曝光确认延迟拖慢 L3 P99。

## 5. 降级、评测与验收

- 将快照新鲜度与 `policy_mode` 写入每次决策；过期时使用获批缓存、neutral 调整或相关性基线，不能默认为任一组欠曝。
- 离线按窗口回放实际曝光，评估份额偏差、HHI、长尾覆盖、组内/整体效用、负反馈和因状态延迟造成的偏差。
- 线上实验同时观察用户效用、消费质量、投诉/负反馈、主体覆盖、集中度、状态读取 P99、事件迟到率与回退率。
- 验收应覆盖新主体冷启动、分组迁移、多组归属、无合格长尾候选、事件重复、状态回放和策略版本切换。

## 常见误解

- **每个列表都均分才公平**：公平通常是跨请求、跨时间窗的统计目标，逐列表均分会损伤明确意图和用户效用。
- **服务端下发即曝光**：渲染失败和不可见位置会造成系统性偏差，应以真实曝光或批准的校正估计累计。
- **长尾扶持等同于无条件加分**：只可在基础规则后的候选内做受限软调整，且必须观察质量与负反馈。
