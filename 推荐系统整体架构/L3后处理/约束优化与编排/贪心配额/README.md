# 贪心配额

贪心配额按位置选择当前效用最高且不违反计数约束的候选，适合规则清晰、时延敏感的线上场景。它应作用于已经通过[基础规则与约束](../../基础规则与约束/README.md)的候选；实体重复、库存、合规和强频控不应被贪心分数重新交换。

## 1. 输入、输出与配额语义

候选需要稳定效用、`input_index`、所属分组和可展示位置；规则至少声明分组、下限 $L_g$、上限 $U_g$、硬软属性和版本。每个位置的输出除 `candidate_id` 外，还应记录选择分、已用配额、跳过原因和 `fallback_reason`。

| 约束类型 | 语义 | 贪心处理 |
| --- | --- | --- |
| 硬上限 | 某分组最多展示 $U_g$ 个 | 选择前检查，超限即拒绝。 |
| 硬下限 | 某分组至少展示 $L_g$ 个 | 先保留位置或执行可行性前瞻，不能只在最后补救。 |
| 位置资格 | 候选仅可进入指定位置/模块 | 在候选扫描时直接排除。 |
| 软目标 | 运营倾向、轻量覆盖 | 加入比较分；不得覆盖硬约束。 |

仅含硬上限时，可直接按位置扫描最高效用可行项。存在硬下限时，朴素“先选最高分、最后补位”可能耗尽位置，导致本来可行的请求变为不可行；应先为必需分组预留数量，或对每次选择检查剩余位置和剩余可供给候选是否仍能满足所有下限。

## 2. 逐位置决策

对位置 $p$ 和已选集合 $S$，可从仍满足硬约束的候选中选择：

$$
i^*=\arg\max_{i\in C\setminus S,\; feasible(i,p,S)}
\left(w_pu_i+\operatorname{soft\_bonus}(i,p,S)\right).
$$

`feasible` 至少检查候选未使用、位置资格、所有硬上限和下限可达性。比较分相同必须以 `input_index`、`candidate_id` 等稳定键打破平局；每个被跳过候选保留结构化原因，如 `quota_upper_bound`、`position_ineligible` 或 `lower_quota_reservation`。

## 3. 复杂度、空间与性能控制

令 $N$ 为候选数、$K$ 为位置数、$R$ 为候选需检查的有效约束数、$G$ 为配额分组数。朴素逐位置扫描的选择时间为 $O(NKR)$，配额计数和已选集合占 $O(G+K)$ 增量空间，不重复计算候选输入字段。

当只有少量上限规则时，可用按效用排序或分组堆减少重复比较，但多重、重叠配额和下限前瞻会使堆的失效与修复变复杂。不要因宣称 $O(N\log N)$ 而省略每次选择的可行性检查；应按真实规则集压测，并限制进入编排的 $N$、规则数和模块数。

配额状态若来自实时服务，先按分组去重并批量读取；本地扫描通常不是 P99 主因。为状态准备、贪心循环、最终校验各预留独立预算，预算不足时返回当前已验证前缀，再按批准的补位策略选择仍可行候选。

## 4. 最小可运行示例

[greedy_quota.py](./greedy_quota.py) 演示互斥类目分组上的硬上限与硬下限；[example.py](./example.py) 展示高分候选不会耗尽为下限类目保留的位置。

```powershell
python example.py
```

该样例刻意限定为每个候选属于一个静态分组、所有位置等价且规则在请求开始时已完成可行性检查。重叠分组、位置兼容、实时状态和软目标需要使用本页的前瞻/联合求解语义，不能直接复制样例的简化逻辑。

## 5. 降级、日志与评测

- 页面开始前校验 $\sum_g L_g\leq K$、候选供给与重叠规则；失败时输出 `infeasible_reason`，不得伪造满足下限的结果。
- 未达硬下限时默认保留空位或进入明确获批的规则版本回退；未达软目标只记录损失，不视为约束违例。
- 记录每位置候选池大小、比较分、分组计数、跳过原因、规则/状态版本、决策耗时与回退路径。
- 离线比较位置加权效用、硬约束满足率、下限可达率、空位率与相关性稳定排序基线；线上监控 P99、回退率、状态读取失败和候选不足。

## 常见误解

- **贪心天然满足下限**：只检查上限的贪心会在早期填满位置，必须显式保留或前瞻下限。
- **配额只能按类目计数**：作者、商家、模块和业务簇均可计数，但每增加一类重叠分组都会增加状态与回放复杂度。
- **候选不足时直接放宽硬约束**：是否允许放宽属于已批准策略，不是求解器的临场决定。
