# Contextual Bandit

Contextual Bandit 在可控探索预算内选择候选、重排参数或策略版本，并从已观察反馈更新估计。它适合将一次请求近似为“观察上下文 -> 选择动作 -> 观察奖励”的场景；需要将动作对未来候选集、疲劳或多次会话的影响显式建模时，应转向 [Slate 与强化学习](../Slate与强化学习/README.md)。

Bandit 的动作空间只能来自[基础规则与约束](../../基础规则与约束/README.md)后的可行候选或获批策略集合。探索配额仍服从频控、合规、库存和位置约束；Bandit 不能将不合格动作带回列表。

## 1. 动作、奖励与日志

| 项目 | 需要明确的约定 |
| --- | --- |
| 上下文 $x$ | 用户、请求、页面和候选特征的版本；不可使用事后反馈特征。 |
| 动作 $a$ | 单候选、一个重排参数或一个策略版本；动作空间随请求变化时必须记录。 |
| 奖励 $r$ | 点击、有效消费、负反馈惩罚或冻结归因窗的组合；定义缺失/迟到标签。 |
| 倾向 $p(a\mid x)$ | 行为策略选择该动作的概率，不是模型打分，也不是点击率。 |
| 随机化 | 探索率、随机种子/版本和并列规则，保证可回放。 |

对于每次探索，记录完整可行动作集合（或可复现摘要）、选中动作、`propensity`、预测值、上下文特征版本、`policy_id` 和模型版本。固定贪心策略的倾向为 $1$，但它无法覆盖未被选择的动作，不能凭空支持这些动作的离线反事实估计。

## 2. 受限请求时流程

```mermaid
flowchart LR
	A[硬规则后的可行候选] --> B[提取版本化上下文]
	B --> C[批量预测各动作价值]
	C --> D{预算与策略状态可用?}
	D -->|是| E[随机化选择并记录 propensity]
	D -->|否| F[批准的贪心基线]
	E --> G[重排/编排器收口]
	F --> G
	G --> H[最终列表与曝光日志]
```

Bandit 可输出“探索某候选”“采用多样性权重”或“选择一个获批策略”，但最终位置仍要经过列表级约束。不要将每个位置独立采样后拼成列表，除非明确建模了位置、去重和整体 slate 的联合概率。

## 3. 可运行的 epsilon-greedy 示例

[`epsilon_greedy.py`](./epsilon_greedy.py) 实现一个以**预先计算的上下文动作价值**为输入的 epsilon-greedy 选择器，并精确记录所选动作倾向。[`example.py`](./example.py) 只在调用方提供的合格动作中选择：

```powershell
& c:/Users/CodenameCYS/anaconda3/envs/py3.12/python.exe example.py
```

该示例不训练价值模型、不处理多位置列表，也不写入真实曝光状态；它展示的是可回放的随机化与日志语义，而不是完整生产 Bandit 系统。

## 4. 复杂度、回退与评测

令 $A$ 为本次可行动作数、$F$ 为每个动作特征数。在线预测通常为 $O(AF)$，选取最大预测值和计算 epsilon-greedy 概率为 $O(A)$，额外工作区为 $O(A)$。候选很多时先用 L2 截断动作集合，避免对所有召回候选做探索打分。

- 特征、预算或模型超时：使用批准的贪心基线，记录 `policy_mode=baseline`，不进行未记录概率的“随机试试”。
- 离线评估前验证 $0 < p(a\mid x) \leq 1$、动作支持集重叠、候选集记录和策略版本一致性；极小 propensity 会造成 IPS 方差爆炸。
- 线上同时监控奖励、探索率、propensity 分布、曝光质量、负反馈、频控命中、延迟与回退率；奖励改善必须按用户与流量切片复核。
