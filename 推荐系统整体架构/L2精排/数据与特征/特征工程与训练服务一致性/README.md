# 特征工程与训练服务一致性

特征工程回答的是：在一次请求发生时，模型可以合法、稳定地使用哪些信息，并如何在训练与服务中得到相同数值。特征分为用户、物品、上下文、行为序列、交叉特征和 L1 来源特征；每个特征必须具备定义、owner、可用时刻、更新频率、默认值、敏感等级与 schema 版本。

本页聚焦特征合同与离在线一致性。请求时刻、候选集和展示事实由[样本空间与曝光归因](../样本空间与曝光归因/README.md)定义；标签成熟时间见[标签定义与时间窗口](../标签定义与时间窗口/README.md)。特征不能在样本或标签边界之外重新定义它们。

## 1. 特征生命周期与数据合同

一项特征应从定义、生产、消费到退役都可审计，而不只是代码中的一个字段名。

| 元数据 | 需要记录的内容 | 解决的问题 |
| --- | --- | --- |
| 名称与业务定义 | 实体、计算公式、单位和取值域 | 同名不同义或指标误用 |
| owner 与来源 | 数据责任人、表/服务、上游版本 | 故障升级和变更治理 |
| 实体与 join 键 | 用户、物品、请求或序列键 | 错连、跨端混淆与泄漏 |
| 可用时刻 | 事件时间、处理延迟、可见条件 | point-in-time 正确性 |
| 新鲜度与 TTL | 更新频率、过期阈值、回退规则 | 陈旧特征与超时降级 |
| 变换规则 | 归一化、分桶、词表、截断与 OOV | 离在线数值不一致 |
| 默认值与缺失语义 | 缺失原因、填充值、缺失标记 | 静默填零掩盖故障 |
| 隐私与敏感等级 | 授权范围、脱敏和保留期限 | 合规与访问控制 |
| schema 版本 | 新旧字段的兼容和发布时间 | 回放与灰度可复现 |

特征发布应以 schema 为边界：训练数据、特征服务、模型输入和监控配置消费同一版本定义。删除或改义特征时，需要保留兼容窗口与回滚路径。

## 2. 特征类型与所有权

| 类型 | 例子 | 时间语义与风险 |
| --- | --- | --- |
| 用户特征 | 长期偏好、活跃度、会员状态 | 注意跨端合并与状态延迟 |
| 物品特征 | 类目、价格、库存、内容质量 | 库存和状态需按请求时间取快照 |
| 上下文特征 | 场景、设备、时间、网络、入口 | 请求级字段不可被跨请求复用 |
| 行为序列 | 最近点击、消费、购买序列 | 事件时间排序、去重与截断必须一致 |
| 交叉特征 | 用户兴趣与物品类目匹配 | 离在线交叉公式和缺失处理一致 |
| L1 来源特征 | 通道、原始分、排名、召回原因 | 需明确分数方向、归一化和候选版本 |

特征 owner 不必与模型 owner 相同，但必须明确谁对含义、时效、质量和变更通知负责。尤其是 L1 分数、库存、风控状态等跨服务特征，应保存来源版本和获取时间。

## Point-in-time 原则

训练样本只能使用请求时刻已可得的信息。对请求时刻 $t_r$，任一特征值 $f$ 应来自其可用时间不晚于 $t_r$ 的记录：

$$
f(t_r)=\operatorname{latest}\{f_k\mid t^{available}_k\le t_r\}
$$

历史序列按事件时间排序并按同一规则截断、去重；热门度、库存和统计量必须从当时快照读取。未来点击、L3 最终位置、人工结果标签属于泄漏。若事件时间和数据到达时间不同，应以在线实际可见时间判断可用性，而不只看事件发生时间。

序列、窗口统计和词表都要写明边界：是否包含当前请求、最大长度、时间窗、重复行为规则、冷启动默认值和迟到事件处理。训练侧用“全量最终数据”重算而服务侧只能看到实时到达数据，是最常见的隐性泄漏来源之一。

## 3. 离在线一致性验证

一致性不止是“同一个字段存在”。离线重放与在线服务必须对同一请求、同一候选、同一 schema 产生相同或在可解释容差内的输入值。

| 对账对象 | 必查内容 | 常见不一致 |
| --- | --- | --- |
| 词表与编码 | ID 映射、OOV、哈希种子、截断 | 在线新值全落入 OOV |
| 数值变换 | 单位、归一化参数、分桶边界、缺失填充 | 离线使用全量统计量 |
| 序列特征 | 顺序、窗口、最大长度、去重与迟到事件 | 在线少事件或包含当前行为 |
| 统计与快照 | 聚合截止时间、TTL、库存/热度版本 | 训练使用未来统计 |
| L1 输入 | 通道名、原始分方向、排名、候选版本 | 通道改名或分数尺度改变 |
| 模型输入 | 字段顺序、dtype、默认值、schema | 服务静默丢字段或类型转换 |

推荐使用固定请求回放集：从日志重建候选与请求时刻特征，分别通过离线管道和在线同构逻辑计算，再比较特征哈希、逐字段差异、缺失率和最终预测差异。差异应按场景、设备、物品年龄和用户活跃度切片，而不能只报告整体平均值。

## 4. 发布、降级与可观测性

特征服务不是永远可用的。每项关键特征要定义超时、缺失、陈旧和 schema 不兼容时的行为：请求失败、使用最近快照、使用业务默认值或降级到不依赖该特征的模型。选择哪种行为取决于特征重要性、风险和服务时延预算，但必须在训练与线上评测中模拟。

| 运行状态 | 建议处理 | 必须监控 |
| --- | --- | --- |
| 正常返回 | 使用当前 schema 与值 | 延迟、覆盖率、新鲜度 |
| 部分缺失 | 采用版本化默认值并置缺失标记 | 缺失率、缺失原因和预测偏移 |
| 超时或上游故障 | 降级快照、简化模型或保守排序 | 超时率、降级比例、体验护栏 |
| schema 不兼容 | 拒绝发布或回滚兼容版本 | 解析错误、版本覆盖与回滚时长 |
| 分布突变 | 暂停扩量并定位来源 | PSI/分位数、OOV、分桶占比 |

发布前应以影子流量或回放请求验证新旧 schema；灰度期间对比特征覆盖、延迟、预测分布和线上护栏。训练服务偏差往往比更换模型更容易造成线上回退。

## 5. 质量检查

1. 离在线词表、归一化、分桶和 OOV 策略一致。
2. L1 通道、原始分方向、排名和候选版本一致。
3. 特征缺失、超时、陈旧值与默认值在线上可观测，并可按原因切片。
4. 回放请求时比对特征哈希、逐字段差异、缺失率与预测差异。
5. 按场景、物品年龄、用户活跃度和设备监控分布漂移与 OOV 比例。
6. 对含敏感数据的特征检查权限、脱敏、保留期限和删除链路。

## 常见误解

- **离线特征计算正确就足够**：线上还需要相同的词表、窗口、默认值和更新时延。
- **缺失值可以静默填零**：默认值本身应是可观测、可版本化的特征语义。
- **事件时间早于请求就一定可用**：数据可能尚未到达服务侧，应按实际可用时间判断。
- **特征服务降级只影响少数请求**：缺失与超时会集中在特定设备、地域或高峰期，必须分群监控。
