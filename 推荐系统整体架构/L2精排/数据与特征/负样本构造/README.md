# 负样本构造

未发生行为不自动等于负反馈。负样本描述的是“在给定任务、曝光口径和观察窗口下，尚未观察到目标行为”的证据，其可信度取决于用户是否真正获得注意机会、标签是否成熟，以及样本是否被旧策略选择性展示。

本页只讨论如何构造任务可用的负向证据。曝光事实和请求内候选语义见[样本空间与曝光归因](../样本空间与曝光归因/README.md)，目标行为与成熟窗口见[标签定义与时间窗口](../标签定义与时间窗口/README.md)，展示策略带来的系统性偏差见[偏差与去偏](../偏差与去偏/README.md)。每个负例来源都应随样本保存 `source`、采样概率、过滤规则和版本。

## 1. 负向证据的层级

从“完全没有交集”到“明确拒绝”，不同记录表达的负向证据强度不同：

| 记录状态 | 能否直接作为负例 | 合理用途 | 主要限制 |
| --- | --- | --- | --- |
| 未被召回或未曝光 | 否 | 召回覆盖分析、随机表示学习 | 没有用户反馈语义 |
| 返回但未渲染 | 通常否 | 客户端链路监控 | 用户可能完全未见到 |
| 渲染但未进入视口 | 谨慎 | 有可见性校正时的辅助信号 | 注意机会不确定 |
| 有效曝光后未点击 | CTR 通常可用 | 点击任务的主要负例 | 位置与展示偏差 |
| 点击后未转化 | CVR 可用 | 条件转化任务的主要负例 | 只代表点击条件下未转化 |
| 主动跳过、屏蔽或投诉 | 视任务可用 | 负反馈目标或约束信号 | 严重度、误触和撤销 |

因此，“负例”应始终带任务前缀，例如“有效曝光 CTR 负例”或“点击条件 CVR 负例”，而不是脱离上下文的 `negative=1`。

## 2. 按任务选择来源

| 来源 | 适用任务 | 主要风险 |
| --- | --- | --- |
| 有效曝光未点击 | CTR | 位置与可见性偏差 |
| 点击未转化 | CVR | 仅在点击条件下成立 |
| 同请求其他候选 | Pairwise/Listwise | 未渲染候选语义弱 |
| 随机候选 | 表示学习、冷启动 | 过易且非曝光反馈 |
| 高分未反馈难例 | 决策边界 | 假负例、延迟转化 |

“未曝光”不能作为用户不喜欢的证据；未进入视口也不应直接标负。CTR 应以有效曝光未点击为起点，并按位置、场景和页面批次分层；CVR 只能在点击或明确意图样本中构造；Pairwise/Listwise 应优先使用同请求、可回放的竞争候选，不能用跨请求的随机物品替代。

## 3. 采样、校正与可追溯性

大规模曝光日志常需要下采样负例。若原始样本以概率 $q_i$ 被保留，训练或评估应至少保存 $q_i$，以便使用逆采样概率权重或在离线评测中恢复分布：

$$
w_i=\frac{1}{q_i}
$$

权重是否直接用于损失函数取决于目标、数值稳定性和系统偏差处理方案；但不保存采样概率，就无法再判断模型变化来自训练方法还是负例分布变化。

建议每条负例保存：来源类型、原始曝光事件、采样概率、分层键、采样时间、成熟状态、过滤原因、候选/标签/采样版本。按位置、场景、用户活跃度和物品热度分层采样时，应同时保存分层规则，避免头部位置或热门物品主导负例集。

## 4. 难负例与假负例控制

难负例通常是与正例相近、当前模型分数较高、但在成熟窗口中未产生目标行为的候选。它能帮助模型学习决策边界，却比随机负例更容易混入延迟反馈、未被看见或本应由其他目标解释的假负例。

| 难例来源 | 使用前提 | 控制方法 |
| --- | --- | --- |
| 同请求高分未点击候选 | 有效曝光与窗口成熟 | 控制位置分布，排除未可见候选 |
| 当前模型高分未转化候选 | 点击条件和转化窗口成熟 | 按模型版本生成并保留版本 |
| 相似物品替代项 | 物品相似度可靠且有同场景竞争 | 限制比例，避免只学习局部相似性 |
| 旧模型常推未反馈候选 | 曝光策略日志完整 | 防止旧策略偏差被放大 |

难例应采用“生成 - 成熟 - 审计 - 过期”的生命周期：只从成熟样本生成、记录挖掘模型和日期、定期刷新，并与随机或曝光负例混合。难例比例突然升高、正负特征距离异常缩小或线上校准恶化时，应先检查假负例，而非继续提高挖掘强度。

## 5. Pairwise 与 Listwise 构造

Pairwise 样本应比较同一请求或相同决策上下文中的候选 $(i^+,i^-)$，其中 $i^+$ 的目标行为强于 $i^-$；Listwise 样本则保留请求级候选集合及其多级反馈。两者都需要候选集合、展示状态、位置与版本，不能把跨请求随机物品拼接成“竞争对”。

| 构造方式 | 最小输入 | 适用目标 | 常见失真 |
| --- | --- | --- | --- |
| Pointwise | 单条成熟曝光与标签 | CTR、CVR、多任务预测 | 忽略请求内竞争 |
| Pairwise | 同请求正负候选与顺序 | 相对偏好、排序损失 | 位置和可见性不一致 |
| Listwise | 可回放候选集与分级标签 | NDCG、列表排序 | 候选缺失或跨请求拼接 |

当一个请求内没有可靠正例或有效曝光负例时，应允许该请求不参与对应 Pairwise/Listwise 任务，而不是用全库随机候选凑齐样本数。

## 6. 质量检查

- 按来源、位置、场景、用户活跃度、物品热度和候选通道报告负例占比，监控分布漂移。
- 检查负例成熟率、后续转正率、撤销率和未归因率，发现延迟反馈或假负例堆积。
- 比较采样前后正负比例及关键特征分布，确认采样没有改变任务定义。
- 审计同请求 Pairwise/Listwise 样本的候选完整率与渲染覆盖率，避免把未展示候选当作失败候选。
- 将采样规则与标签、模型版本联动记录，离线结果只在相同样本契约内比较。

## 常见误解

- **全库随机未点击物品都是负例**：未被展示的物品缺少用户反馈语义。
- **难负例越多越好**：难例比例与成熟窗口需要控制，避免假负例主导训练。
- **点击未转化可以作为所有任务的负例**：它只在点击条件下说明未转化，不能替代 CTR 负例。
- **负采样只是缩小数据量的工程优化**：采样会改变训练分布，必须记录概率、分层和版本。
