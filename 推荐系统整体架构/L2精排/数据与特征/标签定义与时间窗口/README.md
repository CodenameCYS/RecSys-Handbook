# 标签定义与时间窗口

标签定义决定模型究竟在学习什么。相同的“点击率模型”可能分别学习渲染后点击、视口后点击或会话内首次点击；相同的“转化模型”也可能分别对应点击后购买、曝光后购买或跨端购买。若事件主体、归因关系、观察窗口和成熟规则未固定，离线指标的提升没有稳定业务含义。

本页定义标签契约与时间规则。样本何时构成有效曝光见[样本空间与曝光归因](../样本空间与曝光归因/README.md)；“未发生行为”何时可以被采为负例见[负样本构造](../负样本构造/README.md)；如何处理展示偏差见[偏差与去偏](../偏差与去偏/README.md)。

## 1. 标签契约

每个标签应作为一个可版本化的数据产品，最少写清下列内容。

| 契约项 | 要回答的问题 | 示例 |
| --- | --- | --- |
| 业务事件 | 什么事实构成正例 | 点击卡片、完成购买、主动屏蔽 |
| 观察对象 | 针对哪类曝光或意图样本定义 | 有效曝光、已点击、已加购 |
| 归因键 | 如何将行为连接到曝光 | `request_id + item_id`、最近有效点击 |
| 归因窗口 | 多久内发生才计入 | 点击后 24 小时购买 |
| 去重规则 | 多次行为如何计数 | 会话内首次点击、订单级去重 |
| 成熟条件 | 何时可确认未发生 | 24 小时窗口结束且反馈回流完成 |
| 撤销/修正规则 | 退款、取消或误触如何回写 | 退款后取消购买正例 |
| 标签版本 | 规则改变如何追踪 | `conversion_label_v3` |

对样本时刻 $t$，可将一个窗口标签形式化为：

$$
y^{(a,W)}_t=\mathbb{1}\left(\exists\, e_a\in[t,t+W]\ \text{且}\ e_a\ \text{满足归因规则}\right)
$$

其中 $a$ 是行为类型，$W$ 是观察窗口。该定义只描述“窗口内是否发生”，不自动说明窗口尚未结束时应如何训练。

## 2. 常用标签及其业务语义

| 标签 | 常见正例定义 | 常用窗口 | 需要排除、修正或单独记录的事实 |
| --- | --- | --- |
| 点击 | 有效曝光后的明确点击 | 当前请求或会话 | 渲染失败、误触、重复点击、跳转失败 |
| 有效消费 | 达到最小时长、阅读深度或完成率 | 点击后或曝光后短窗口 | 内容长度、后台播放、快速跳出、自动播放 |
| 转化 | 加购、购买、预约或支付成功 | 小时到数日 | 取消、退款、跨端归因、库存失败 |
| 负反馈 | 不喜欢、屏蔽、投诉等主动行为 | 较长窗口 | 误触、系统自动操作、撤销和严重度 |
| 留存/复访 | 次日或多日再次活跃 | 日到周 | 用户级归因、自然回访与标签未成熟 |

同一次曝光可以产生多种标签。例如点击、有效消费和购买并非互斥，通常应保留为多任务目标，而不是压缩为一个混合标签。任务之间的样本空间与漏斗关系应显式记录，避免把“未点击”误当成“点击后未购买”。

## 3. 时间轴与成熟度

每条样本至少涉及请求发生时间 $t_r$、特征可用时间 $t_f$、行为发生时间 $t_e$ 和标签成熟时间 $t_m$，并且必须满足：

$$
t_f\le t_r < t_e\le t_m
$$

训练特征只能使用 $t_r$ 时已可获得的信息。对于窗口为 $W$ 的转化标签，通常有 $t_m=t_r+W+\delta$，其中 $\delta$ 是日志回流、撤销或订单状态稳定所需的缓冲时间。在 $t_m$ 之前，尚未转化的样本是右删失或未知状态，不是可靠负例。

| 处理方式 | 做法 | 适用条件 | 代价 |
| --- | --- | --- | --- |
| 仅使用成熟样本 | 只保留窗口和缓冲均结束的样本 | 追求稳健基线 | 数据新鲜度下降 |
| 延迟回填 | 先生成候选样本，成熟后写入最终标签 | 数仓支持可追溯回填 | 需要版本与重跑管理 |
| 删失/生存建模 | 显式建模事件发生时间与观察终止 | 转化延迟差异大 | 目标与实现更复杂 |
| 多阶段目标 | 快速反馈与慢标签联合训练 | 需快速迭代且有长期目标 | 防止短期信号主导 |

## 4. 归因、重复行为与冲突标签

同一用户同一物品可被多次曝光，也可能跨端完成转化。应预先定义归因策略，而不是在样本生成时临时选择。

| 场景 | 常见选择 | 需要额外检查 |
| --- | --- | --- |
| 同请求重复展示 | 请求内去重或归因给首个可见位置 | 去重是否改变位置含义 |
| 连续多次曝光后点击 | 最近触点、首触点或多触点归因 | 归因窗口与曝光序列完整性 |
| 点击后跨端购买 | 登录用户跨端关联或渠道规则 | 身份映射覆盖与隐私授权 |
| 购买后退款 | 以订单最终状态回写 | 回写延迟与已训练样本修订 |
| 点击并主动屏蔽 | 保留多标签并定义各自窗口 | 负反馈发生顺序与严重度 |

归因规则会直接改变标签分布和任务难度，应随标签版本一起记录在实验报告中。

## 5. 标签生成与质量检查

标签生成应从冻结的曝光事实开始，按标签版本关联反馈事件、等待成熟，再写入训练样本。建议为每条样本保留 `label_version`、窗口起止时间、成熟状态、归因事件 ID 和撤销状态，便于回填与审计。

- 按天监控各标签正例率、成熟率、延迟分布和回填量，识别埋点或业务流程突变。
- 比较请求、曝光、点击、转化、退款之间的漏斗覆盖率，检查 join 错配和重复计数。
- 按场景、位置、设备、用户活跃度和物品年龄切片，避免总体均值掩盖标签缺失。
- 对抽样样本做人工或业务系统核验，确认误触、自动行为、取消和退款处理正确。
- 固定训练、验证和测试的标签版本与成熟截止时间，禁止测试期标签规则反向影响训练集。

## 常见误解

- **没有立即转化就代表负反馈**：转化标签需要等待既定窗口与反馈回流缓冲完成。
- **同一行为天然只属于一次曝光**：跨会话与重复曝光场景需要明确归因策略。
- **标签窗口越长越准确**：更长窗口会降低数据新鲜度并增加无关触点，需要与业务决策周期匹配。
- **点击、转化和负反馈可以压成一个标签**：它们反映不同阶段与价值维度，通常应保留多任务语义。
