# Listwise

Listwise 以一次请求的候选集合为训练单位，直接描述同一列表内各候选的联合竞争关系。它适合优化前 K 展示顺序、分级相关性或列表效用，但前提是请求级候选、展示链路与反馈都可以被可靠回放。

本页讨论 L2 阶段的请求内排序目标。请求候选集、渲染和视口口径见[数据与特征：样本空间与曝光归因](../../数据与特征/样本空间与曝光归因/README.md)，标签定义见[标签定义与时间窗口](../../数据与特征/标签定义与时间窗口/README.md)。L2 的 Listwise 目标不等同于 L3 的多样性、合规和频控等列表约束。

## 1. 请求列表契约

对请求 $r$，训练样本为候选集合 $\mathcal C_r=\{i_1,\ldots,i_n\}$、请求上下文 $x_r$、每个候选的特征和分级标签 $rel_j$。至少应保存候选集合版本、L1 来源、L2 分数、L3 前后位置、渲染/视口状态、实验版本与标签成熟状态。

| 列表事实 | 为什么影响训练 | 缺失后的风险 |
| --- | --- | --- |
| 完整候选集合 | 定义谁在同一次请求中竞争 | 随机拼接导致伪列表 |
| 候选资格与去重 | 区分不可展示与被排低 | 把规则过滤误当模型失误 |
| 展示与视口 | 定义真实注意机会 | 未见候选被当作低相关 |
| 分级行为标签 | 表达点击、消费、转化强弱 | 只剩稀疏二值反馈 |
| L3 调整记录 | 划分 L2 与后处理责任 | 离线列表与线上曝光不一致 |

候选数可变是正常的，但 padding、截断、最大候选数和无正例请求的处理必须固定。不能为了凑齐列表而跨请求拼接候选，也不能将未回放完整的请求用于请求级 NDCG 结论。

## 2. 常见 Listwise 目标

softmax 交叉熵将一个请求中的目标候选建模为条件分布：

$$
P(i\mid x,\mathcal C)=\frac{\exp(s(x,i))}{\sum_{j\in\mathcal C}\exp(s(x,j))}
$$

当一个请求有多个正例或分级反馈时，可将 $rel_j$ 转为目标分布或使用加权 softmax。LambdaRank/LambdaMART 一类方法依据交换两个候选引起的 $\Delta NDCG$ 加权梯度，更直接关注前 K 的排序收益。

$$
\lambda_{jk}\propto \left|\Delta NDCG@K_{jk}\right|
\cdot \sigma\left(s_k-s_j\right)
$$

| 目标形式 | 适用反馈 | 优点 | 关键限制 |
| --- | --- | --- | --- |
| Softmax/多项式交叉熵 | 单点击或归一化偏好 | 实现直接，列表内竞争明确 | 多正例与未点击语义需定义 |
| 分级相关性损失 | 点击、消费、转化等级 | 利用行为强弱 | 等级映射可能混入业务权重 |
| LambdaRank 类 | 优化 NDCG@K | 更重视前 K 交换 | 依赖可靠分级标签与请求列表 |
| Listwise + Pointwise | 同时追求顺序和概率 | 可服务融合与校准 | 需调节损失权重 |

## 3. 曝光偏差与 L3 边界

Listwise 训练使用整页候选并不会自动消除位置偏差：旧策略仍决定谁被展示、谁进入视口以及谁获得行为标签。应保留位置和可见性，并按位置、场景和请求长度切片评测；有可信探索概率时再考虑反事实诊断。

L2 的目标是为候选提供可比较的相关性或效用分数。多样性、去重、供给、合规、频控与最终页面布局通常由 L3 统一处理。若将这些规则事后造成的展示变化直接回灌为 L2 负标签，模型会混淆“用户不喜欢”与“系统不允许展示”。

## 4. 训练与评测检查

1. 固定请求 ID、候选集合版本、截断长度、padding/mask 语义和无正例请求的处理。
2. 对比 L2 输入候选、L3 前列表、L3 后列表与实际渲染列表的覆盖率，明确每个离线指标对应哪一层。
3. 以请求为单位计算 NDCG@K、MRR、MAP 或 Recall@K，$K$ 与实际可见/曝光长度一致。
4. 按请求长度、位置、场景、候选通道、用户活跃度和物品年龄切片，检查列表构成漂移。
5. 与 Pointwise、Pairwise 做消融，分离“列表损失有效”与“候选集或标签规则变化”的影响。
6. 线上验证同时观察短期点击、后续转化、负反馈和 L3 护栏，避免仅提升列表内点击集中度。

## 常见误解

- **Listwise 天然等同于最终页面排序**：训练列表与 L3 最终列表之间仍存在规则与约束层。
- **使用整页候选就没有曝光偏差**：候选来源与位置机制仍会影响观测标签。
- **候选越多，Listwise 一定越接近线上**：超出实际可竞争范围的候选会稀释损失并增加回放误差。
- **无点击请求没有训练价值**：它们可用于特定曝光或负反馈任务，但必须先定义其标签语义。
