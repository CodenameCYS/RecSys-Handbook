# LSH：局部敏感哈希

局部敏感哈希（Locality-Sensitive Hashing, LSH）不是普通哈希。普通哈希追求输入稍有变化，哈希值就完全不同；LSH 恰好相反，它专门设计一种哈希族，让距离近的向量以更高概率得到相同哈希值。

本目录实现的是适用于余弦相似度的随机超平面 LSH，也称 SimHash 风格的向量哈希。

## 核心直觉

在二维平面中，用一条穿过原点的直线把空间分成两侧。两个方向接近的向量大概率落在同一侧，夹角很大的向量则更容易落在不同侧。推广到 $d$ 维后，这条分界线变成一个经过原点的随机超平面。

为随机超平面采样一个法向量 $\boldsymbol r$，定义一位哈希：

$$
h_{\boldsymbol r}(\boldsymbol x)
= \begin{cases}
1, & \boldsymbol r^{\mathsf T}\boldsymbol x \ge 0 \\
0, & \boldsymbol r^{\mathsf T}\boldsymbol x < 0
\end{cases}
$$

点积的正负表示向量位于超平面的哪一侧。若两个向量夹角为 $\theta$，随机超平面把它们分开的概率为 $\theta / \pi$，落在同一侧的概率为：

$$
P\bigl(h(\boldsymbol x)=h(\boldsymbol y)\bigr)
= 1 - \frac{\theta(\boldsymbol x,\boldsymbol y)}{\pi}
$$

这就是“局部敏感”的来源：余弦越相似，夹角越小，两者哈希位相同的概率越高。

## 从一位哈希到哈希桶

一位哈希只能把空间分成两半，桶太大，无法明显减少扫描量。因此一张哈希表会使用 $b$ 个独立随机超平面，产生 $b$ 位签名：

$$
g(\boldsymbol x)
= \bigl(h_1(\boldsymbol x), h_2(\boldsymbol x), \ldots, h_b(\boldsymbol x)\bigr)
$$

例如签名 `10110` 可以编码成一个整数作为桶键。只有全部 $b$ 位都相同的向量才进入同一个桶。位数越多，桶通常越小，查询更快；但近邻只要有一位不同就可能被分开，召回会下降。

为了降低这种偶然漏召回，LSH 通常构建 $L$ 张相互独立的哈希表。查询分别进入每张表的对应桶，最后取候选并集。只要真正近邻在任意一张表中与查询碰撞，就有机会被召回。

## 构建过程

1. 为每张表随机生成 $b$ 个 $d$ 维超平面法向量。
2. 对每个商品向量，计算它与全部超平面的点积。
3. 将点积正负转换成二进制签名。
4. 在每张表中记录 `签名 -> 向量位置列表`。
5. 另行保存原始向量，以便对候选做精确重排。

索引主要由随机超平面矩阵、多个哈希桶和原始向量组成。它不需要像 K-Means 那样训练数据分布，因此新增向量只需计算签名并追加到对应桶，增量写入较直接。

## 查询过程

1. 使用每张表自己的随机超平面计算查询签名。
2. 读取查询签名对应的桶，合并不同表中的候选位置。
3. 若候选太少，执行 multi-probe：继续访问与查询签名汉明距离较小的桶。
4. 对候选向量计算精确余弦相似度。
5. 返回精确重排后的 Top-K。

两个签名的汉明距离是不同二进制位的数量。例如 `10110` 与 `10011` 有两位不同，汉明距离为 2。优先探测汉明距离为 1、2 的桶，相当于逐步放宽“必须位于所有超平面同一侧”的要求。

需要注意：签名接近只是候选生成条件，不应直接当作最终向量相似度。最终精排能消除哈希碰撞产生的大量假阳性。

## 参数为何影响效果

| 参数 | 增大后的主要效果 | 代价或风险 |
| --- | --- | --- |
| `num_bits` | 桶变小，单桶扫描减少 | 碰撞概率下降，可能漏掉近邻 |
| `num_tables` | 真近邻至少碰撞一次的概率上升 | 超平面、桶和重复候选占用更多内存 |
| 探测桶数 | 候选更多，Recall@K 通常提高 | 查询延迟增加 |
| `candidate_target` | 精确重排的候选更多 | 算分成本增加 |

参数之间必须联调。增加位数后，通常要增加表数或 multi-probe 范围来补偿召回；只单独把某个参数调大，常常无法获得预期结果。

[index.py](./index.py) 中：

示例为了便于理解，会对当前表中已有的全部桶按汉明距离排序。生产 multi-probe LSH 通常直接生成有限个邻近签名，而不是遍历整张表，否则桶路由本身可能成为瓶颈。

## 适用场景与限制

LSH 适合需要无训练增量写入、哈希分片或分布式桶路由的场景。它的桶键天然可以作为分区键，也容易把多张表分散到不同机器。

主要限制是维度升高或要求高 Recall@K 时，往往需要很多哈希表和探测桶，内存与候选数会迅速上升。数据分布偏斜时还可能产生超大桶，因此需要监控桶大小分位数、空桶率、重复候选率和每次查询的实际候选数。

随机超平面 LSH 专门保持角度关系。若目标是欧氏距离、Jaccard 相似度或其他度量，应选择与该度量匹配的 LSH 哈希族，不能直接照搬本实现。
