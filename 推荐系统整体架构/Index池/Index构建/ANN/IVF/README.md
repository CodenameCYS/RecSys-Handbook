# IVF：倒排文件索引

倒排文件索引（Inverted File Index, IVF）先把向量空间划分成许多区域，再把每个商品挂到所属区域的倒排列表中。查询时不再扫描整个 Index 池，只扫描最可能包含近邻的少数区域。

这里的“倒排”与文本检索中的倒排索引思想相同：文本索引由词项找到包含它的文档，IVF 则由聚类中心找到属于该空间区域的向量列表。

## 核心直觉

假设要在全国寻找离某个地址最近的门店。Flat 相当于计算该地址到全国每家门店的距离；IVF 则先按城市或片区分组，判断查询最接近哪些片区，再只比较这些片区内的门店。

IVF 用 $K$ 个聚类中心 $\{\boldsymbol c_1, \ldots, \boldsymbol c_K\}$ 表示这些空间区域。每个向量分配给最近的中心：

$$
a(\boldsymbol x)
= \underset{j \in \{1,\ldots,K\}}{\operatorname{argmin}}
\|\boldsymbol x - \boldsymbol c_j\|_2^2
$$

这个“用最近中心表示向量所属区域”的过程也称为粗量化（coarse quantization）。中心只是路由入口，不是最终结果；倒排列表中仍保存该区域内的商品向量或其压缩编码。

## 索引由什么组成

一个基础 IVF 索引包含三部分：

1. **粗量化器**：$K$ 个聚类中心，用于把查询和商品路由到空间区域。
2. **倒排列表**：`cluster_id -> [vector_position, ...]`，记录每个区域中的向量位置。
3. **向量与 ID 存储**：保存原始向量用于候选精确算距，并保存位置到业务 ID 的映射。

如果倒排列表保存完整 `float32` 向量，通常称为 IVF-Flat。若列表中保存 PQ 压缩码，则是 IVF-PQ。

## 训练与构建过程

### 1. 训练粗量化器

从具有代表性的生产向量中采样，使用 K-Means 最小化簇内平方误差：

$$
\underset{\{\boldsymbol c_j\}}{\operatorname{minimize}}
\sum_{i=1}^{N}\|\boldsymbol x_i - \boldsymbol c_{a(\boldsymbol x_i)}\|_2^2
$$

K-Means 交替执行两步：先把每个训练向量分配给最近中心，再用簇内向量均值更新中心，直到中心基本稳定或达到迭代次数。

训练集必须覆盖线上向量分布。若只用旧内容、单一类目或过小样本训练，中心不能正确描述生产空间，查询容易被路由到不合适的桶。

### 2. 填充倒排列表

对每个建库向量计算最近中心，把其内部位置追加到对应倒排列表。理想情况下，每个桶约有 $N/K$ 个向量；实际数据往往不均匀，因此需要监控最大桶、桶大小分位数和空桶率。

## 查询过程

1. 计算查询 $\boldsymbol q$ 到全部 $K$ 个中心的距离。
2. 选出最近的 `nprobe` 个中心。
3. 合并这些中心对应的倒排列表，形成候选集。
4. 对候选与查询计算精确距离。
5. 从候选中选出 Top-K，并映射回业务 ID。

如果 `nprobe = 1`，只扫描查询所属的最近区域，速度快但边界附近容易漏召回。例如查询靠近两个簇的分界线时，真正近邻可能被分到相邻簇。增加 `nprobe` 就是在查询时跨越更多区域边界。

当 `nprobe = nlist` 时，所有倒排列表都会被扫描，IVF-Flat 的结果退化为 Flat，近似误差消失，但加速也随之消失。

粗略地说，桶较均匀时每次扫描的候选数约为：

$$
N_{\text{scan}} \approx N \times \frac{\text{nprobe}}{\text{nlist}}
$$

这只是估算；热点桶、过滤条件和查询分布都会使真实扫描量偏离该值。

## 参数为何影响效果

| 参数 | 增大后的主要效果 | 代价或风险 |
| --- | --- | --- |
| `nlist` / `num_clusters` | 空间划分更细，单桶通常更小 | 中心路由更贵，需要更多训练数据，桶可能变空或倾斜 |
| `nprobe` | 跨更多桶搜索，Recall@K 提高 | 候选扫描量和延迟增加 |
| 训练样本数 | 中心通常更稳定、更符合分布 | 训练时间和内存增加 |
| K-Means 迭代数 | 聚类可能更充分 | 收益会逐渐饱和，训练成本增加 |

`nlist` 决定索引的长期空间划分，通常在构建时确定；`nprobe` 是在线查询旋钮，可以按延迟预算、流量等级或查询难度动态调节。

## 与示例代码的对应关系

[index.py](./index.py) 中：

- `IVFIndex.train`：随机选择初始中心并执行简化 K-Means。
- `assignments = np.argmin(distances, axis=1)`：把训练向量分配给最近中心。
- `members.mean(axis=0)`：用簇内均值更新中心。
- `IVFIndex.add`：为建库向量分桶并填充 `_inverted_lists`。
- `selected_clusters`：选出距离查询最近的 `nprobe` 个中心。
- `positions`：合并被探测桶中的候选。
- 最后的距离计算：对候选执行精确 L2 重排。

运行示例：

```powershell
python .\index.py
```

该 NumPy 实现为了展示机制，会显式构造“向量数乘中心数”的距离矩阵，只适合教学。FAISS 等生产库会使用分块、SIMD、GPU 或更高效的 K-Means 实现。

## 适用场景与工程风险

IVF 适合能够离线训练、数据规模较大，并希望通过 `nprobe` 明确调节召回与延迟的场景。它也方便按倒排列表分片或结合类目、地域等路由进一步缩小范围。

需要特别关注：

- **分布漂移**：新向量分布明显变化后，旧中心会失效，需要重训和重建。
- **桶倾斜**：热点桶会造成 P99 延迟、机器负载和分片容量不均。
- **过滤后不足**：先 ANN 后业务过滤可能让某些桶返回不够，需要扩大 `nprobe` 或使用过滤感知索引。
- **中心边界漏召回**：近邻落在相邻桶是 IVF 最基本的近似来源。

理解 IVF 的关键是区分两次距离计算：第一次只与少量中心比较，用于选区域；第二次才在选中区域内比较商品向量，用于产生最终 Top-K。
