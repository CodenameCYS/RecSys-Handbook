# I2I 召回

I2I 召回以用户当前或历史物品为种子，查询每个种子的相关物品，再经过多种子聚合、过滤和截断形成用户级候选。它主要解决“当用户已经表达了局部兴趣时，如何快速找到与该兴趣相关、相似、替代、互补或可能作为下一步消费目标的物品”。

I2I 是一种线上召回方向，而不是单一算法。物品关系既可以由共现、文本、属性和知识边直接计算，也可以从矩阵分解、图模型、序列模型、对比学习或多模态模型得到的 embedding 中检索。完整分类和服务流程见 [I2I 召回综述](./I2I召回综述.md)。

## 内容导航

### 非向量召回

- [非向量召回](./非向量召回/README.md)：直接根据内容字段、结构化属性、知识边、规则或路径计算物品关系，并将结果物化为近邻表。
  - [内容与属性相似度](./非向量召回/内容与属性相似度/README.md)：使用文本、类目、标签和结构化属性计算可解释的物品关系。
  - [知识与关系相似度](./非向量召回/知识与关系相似度/README.md)：利用显式关系、知识图谱、规则或路径定义物品关联。

### 向量召回

- [向量召回](./向量召回/README.md)：先学习统一的 item embedding，再通过 ANN 或离线向量近邻生成 I2I 关系。
  - [I2I 原生表示学习](./向量召回/I2I原生表示学习/README.md)：训练目标直接塑造 item-to-item 邻近关系，包含 Item2Vec、监督度量学习、InfoNCE 和 SimCSE-style。
  - [上游任务派生表示](./向量召回/上游任务派生表示/README.md)：复用矩阵分解、图推荐或序列预测任务产生的 item embedding 构建近邻。
  - [表示增强与迁移](./向量召回/表示增强与迁移/README.md)：利用多模态内容、预训练模型和知识蒸馏增强可检索表示。

## 组织逻辑

目录首先按线上近邻的核心产物区分为非向量与向量两类：非向量召回直接计算或查表获得关系，向量召回先得到 item embedding 再执行近邻检索。向量方法进一步按照表示与 I2I 目标的关系拆分：直接优化物品邻近关系的原生表示、从其他推荐任务复用的派生表示，以及可以叠加到前两类方法上的增强与迁移机制。这样的组织方式把“关系如何产生”“表示为何被学习”和“线上如何查询与融合”三个问题分开。经典 ItemCF 的算法细节归入[协同过滤](../协同过滤/README.md)，本目录从 I2I 服务视角引用其近邻产物。
