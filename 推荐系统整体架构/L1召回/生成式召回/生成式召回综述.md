# 生成式召回综述

生成式召回把“在全库中检索候选”改写为“根据用户上下文生成物品标识”。若物品 $i$ 被表示为 token 序列 $(c_1,\ldots,c_M)$，模型学习：

$$
p(i\mid x_u)=\prod_{m=1}^{M}p(c_m\mid x_u,c_{<m})
$$

它不是 Kuaishou 单独提出的一种算法，而是一条包含语义 ID、生成式检索、推荐序列建模和偏好对齐的研究路线。TIGER 是语义 ID 生成检索的重要代表；Kuaishou 的 OneRec 则是工业规模统一生成式推荐的重要工作，应放在完整谱系中理解。

## 一、物品标识

### 原始 ID

直接将 item ID 当作一个类别，简单但输出层随物品规模增长，且 ID 间没有语义共享。本目录的 [model.py](./model.py) 与 [train.py](./train.py) 是 GRU + 全物品分类的最小基线。

### 语义 ID

先用内容或协同 embedding 表示物品，再通过 RQ-VAE/残差量化将向量逐级映射为离散代码。例如 $(12,7,31)$ 可表达从粗到细的语义路径。残差量化逐层选择码字：

$$
c_m=\arg\min_k\lVert r_{m-1}-e_{m,k}\rVert^2,\qquad
r_m=r_{m-1}-e_{m,c_m}
$$

不同物品可能得到同一码序列，需要碰撞消解；码本更新还会改变历史 ID，因此必须版本化，并设计新品分配和索引迁移策略。

## 二、自回归模型

输入通常是按时间排序的交互序列及场景上下文，标签为下一物品的多级代码。Transformer encoder-decoder 或 decoder-only 模型按代码位计算交叉熵：

$$
\mathcal L_{gen}=-\sum_{m=1}^{M}\log p(c_m\mid x_u,c_{<m})
$$

自回归交叉熵不显式枚举传统负样本，但 softmax 中的其他 token 构成竞争项。后续偏好优化、拒绝采样或 reranking 仍可能使用负反馈。

## 三、受约束解码

逐 token 贪心或 beam search 可能生成不存在的代码组合。生产系统通常用合法语义 ID 构建 Trie，在每一步只允许当前前缀的有效后继 token，并叠加库存、地域、合规和去重约束。

- [semantic_id.py](./semantic_id.py)：残差量化、碰撞后缀和合法 ID Trie。
- [semantic_id_example.py](./semantic_id_example.py)：生成语义 ID 并模拟受约束逐步解码。

## 四、代表性路线

- **TIGER**：以语义 ID 和生成模型直接生成推荐目标，体现“检索即生成”的核心范式。
- **HSTU**：重点是大规模推荐序列建模架构，不应简单等同于语义 ID 检索；它说明生成式推荐需要怎样扩展长序列建模能力。
- **OneRec**：Kuaishou 的统一生成式推荐方向，将候选生成、序列建模和偏好对齐推向工业规模。理解时应重点关注 token 化、训练阶段、解码效率、在线约束及与传统召回/排序链路的对照。

## 五、工程评估

除 Recall@K/NDCG@K 外，还要单独测非法 ID 率、重复率、beam 解码时延、语义 ID 覆盖率、码本利用率、碰撞率、新品接入延迟和模型/码本版本兼容性。必须与强双塔 ANN 基线在相同数据、候选规模和时延预算下比较。

安装 PyTorch 后执行 `python train.py`；标准库语义 ID 示例执行 `python semantic_id_example.py`。
