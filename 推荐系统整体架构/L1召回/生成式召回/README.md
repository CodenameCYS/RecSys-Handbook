# 生成式召回

生成式召回根据用户上下文直接生成物品 ID 或语义 ID，将候选检索改写为受约束的序列生成问题。它试图解决传统召回中“先编码查询、再从固定索引检索”的范式限制，让用户序列建模、候选生成和偏好学习能够在统一生成目标下协同优化。

这一方向的核心问题包括如何表示海量物品、如何训练下一物品或语义代码生成模型，以及如何保证解码结果对应真实且当前可推荐的物品。完整原理、代表路线和工程约束见[生成式召回综述](./生成式召回综述.md)。

## 内容导航

- [生成式召回综述](./生成式召回综述.md)：物品标识与 tokenizer、自回归训练、约束解码、典型工作、工业延迟优化、混合部署、优缺点和评估体系。
- [model.py](./model.py)：使用 GRU 根据用户历史预测下一物品的最小生成式召回模型。
- [train.py](./train.py)：原始 item ID 分类基线的样本组织、训练和评估入口。
- [semantic_id.py](./semantic_id.py)：残差量化、语义 ID 碰撞处理和合法 ID Trie。
- [semantic_id_example.py](./semantic_id_example.py)：语义 ID 构建与受约束逐步解码示例。

## 组织逻辑

当前目录先用全物品分类基线说明“根据历史直接预测物品”，再用语义 ID 示例说明如何把巨大输出空间拆成多级代码并限制合法解码路径。两组代码分别对应生成式召回的模型主线和标识/解码主线；更完整的大规模 Transformer、偏好对齐和工业系统设计保留在综述中讨论。
