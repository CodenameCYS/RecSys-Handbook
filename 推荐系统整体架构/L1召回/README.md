# L1 召回

L1 召回位于 Index 池与 L2 精排之间，负责在严格的时延和资源预算下，从百万到十亿级可推荐物品中筛选出规模可控、相关性较高且来源足够多样的候选集合。它解决的核心问题不是对少量候选做精确排序，而是以较低成本尽可能覆盖用户下一步可能感兴趣的物品，为后续排序阶段提供有效搜索空间。

一个工业召回系统通常需要并行部署多种通道：有的方法直接建模用户与物品的匹配，有的方法利用群体行为或当前种子物品扩展候选，还有的方法负责新品、热点、运营供给和主动探索。不同通道产生的候选经过过滤、去重、分数校准和融合后进入 L2 精排。

## 模块划分逻辑

本目录主要按照“候选关系如何产生”和“线上从什么入口发起检索”组织内容：

| 模块 | 主要解决的问题 | 核心方法 | 在召回体系中的作用 |
| --- | --- | --- | --- |
| 双塔召回 | 如何直接计算请求与全库物品的匹配关系 | 用户塔、物品塔、对比学习、负采样、ANN | 提供可泛化的个性化主召回通道 |
| 协同过滤 | 如何从群体交互中提取用户或物品之间的协同关系 | UserCF、ItemCF、MF、BPR、GraphCF | 利用行为共现和潜在偏好补充个性化候选 |
| I2I 召回 | 如何从用户当前或历史物品快速扩展相关物品 | 共现、内容与关系相似度、item embedding、近邻检索 | 捕捉局部兴趣、替代关系、互补关系和序列意图 |
| 生成式召回 | 如何把候选生成改写为物品标识生成 | 语义 ID、自回归模型、约束解码 | 探索检索、序列建模与生成模型的一体化路径 |
| 其他召回方式 | 如何覆盖主模型不擅长的时效、冷启动和业务场景 | 热门、内容、图与知识、规则运营、探索 | 提供兜底、增量覆盖、确定性供给和反馈采集 |

这几类模块并非互斥。例如双塔生成的 item embedding 可以用于 I2I，GraphCF embedding 既可以执行 U2I，也可以构建 item 近邻；内容编码器既可能属于双塔模型，也可能服务于新品召回。这里按主要研究问题拆分，是为了分别讲清数据来源、离线产物、在线触发方式和评测口径，再在召回系统综述中讨论多路融合。

## 内容导航

- [召回系统综述](./召回系统综述.md)：先建立 L1 的任务边界和完整服务链路，理解多路召回如何调度、融合、降级和监控。
- [召回系统评测](./召回系统评测.md)：统一 Recall@K、HitRate@K、覆盖率、增量价值和时间切分等评测口径，避免只比较单一离线指标。
- [双塔召回](./双塔召回/README.md)：介绍请求侧与物品侧如何进入统一向量空间，以及样本构造、塔结构和 ANN 服务之间的关系。
- [协同过滤](./协同过滤/README.md)：介绍如何从交互矩阵和用户-物品图中获得用户近邻、物品近邻及潜在向量。
- [I2I 召回](./I2I召回/README.md)：介绍如何构建多种 item-to-item 关系，并从用户历史种子出发完成多通道候选扩展。
- [生成式召回](./生成式召回/README.md)：介绍如何通过物品标识、序列模型和受约束解码直接生成合法候选。
- [其他召回方式](./其他召回方式/README.md)：介绍热门、内容、知识关系、运营和探索通道如何弥补个性化主召回的覆盖缺口。
- [L1 召回文献](../../文献/L1召回/README.md)：按上述研究问题组织经典工作与前沿论文，供进一步阅读和方案溯源。

## 推荐阅读顺序

建议先读[召回系统综述](./召回系统综述.md)建立系统边界，再通过[召回系统评测](./召回系统评测.md)统一实验口径，之后进入具体方法目录。首次系统学习时，可按“协同过滤 → I2I → 双塔 → 生成式召回”理解从显式共现、潜在表示到端到端检索和生成式建模的演进；设计生产系统时，则应同时阅读[其他召回方式](./其他召回方式/README.md)，补齐热点、冷启动、运营和探索能力。

每个一级模块采用相同的文档结构：模块 `README.md` 解释问题、方法分类和目录组织；独立的“综述”文档负责完整原理与工程链路；下级目录聚焦具体算法或实现。向量索引的构建、发布和版本管理统一由 [Index 池](../Index池/README.md)介绍，避免在每种召回算法中重复说明基础设施。
