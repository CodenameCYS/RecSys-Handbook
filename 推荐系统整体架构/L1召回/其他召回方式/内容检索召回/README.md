# 内容检索召回

内容召回直接利用物品的文本、类目、标签、作者、图像或音频表示匹配用户当前意图。它不依赖目标物品已有交互，因此特别适合新品、低频供给、搜索式请求和跨域迁移，但“语义相似”不等于“用户效用高”，仍需质量先验与行为模型补充。

## 1. 查询与语料构造

查询可以来自显式搜索词、近期行为物品的标签聚合、用户长期兴趣词或场景上下文。物品文档由标题、类目、标签、品牌和内容理解结果组成，不同字段应设置权重。训练与评测时只能使用当时可见的物品内容版本，避免编辑后的文本泄漏。

内容特征需治理缺失、错标、同义词、语言、OOV 和标签作弊。多模态向量还要记录编码器与预处理版本，保证增量物品和存量索引在同一表示空间。

## 2. 三类实现

| 路线 | 机制 | 优点 | 局限 |
| --- | --- | --- | --- |
| 规则/倒排 | 类目、标签或实体精确匹配 | 可解释、过滤方便、更新快 | 召回边界硬，处理不了语义改写 |
| 稀疏检索 | TF-IDF、BM25、学习稀疏表示 | 保留关键词解释，长尾词有效 | 依赖分词，跨模态能力弱 |
| 稠密检索 | 文本/视觉编码器、内容双塔 | 语义泛化和多模态能力强 | 需 ANN，易产生语义同质化 |

稀疏与稠密通常并行，再按 rank 或校准分融合。若内容编码器使用推荐反馈微调，应明确它已不再是纯内容模型，并检查热门曝光偏差是否渗入表示。

## 3. 在线服务与监控

物品内容进入 Index 池后生成倒排项或 embedding；请求侧生成查询表示，执行检索、资格过滤和 Top-K。监控内容覆盖率、编码失败率、索引年龄、OOV 率、查询空结果率、相似度分布、新品覆盖、长尾覆盖和与协同通道的增量命中。

评测除 Recall@K 外，还应按新品/成熟物品、头部/长尾和查询类型分桶，并人工检查语义相关性、安全性与重复内容。只看点击会低估新供给，也可能奖励标题党。
