# 内容检索召回

内容召回直接利用物品的文本、类目、标签、作者、图像或音频表示匹配用户当前意图。它不依赖目标物品已有交互，因此特别适合新品、低频供给、搜索式请求和跨域迁移，但“语义相似”不等于“用户效用高”，仍需质量先验与行为模型补充。

## 1. 方法边界与分类

内容召回的判定标准是候选主要由物品自身内容成立，而不是是否用了向量模型。

| 路线 | 表示与匹配 | 擅长的问题 | 主要局限 |
| --- | --- | --- | --- |
| 属性/倒排召回 | 类目、标签、品牌、实体精确匹配 | 强约束、可解释筛选、新品 | 边界硬，依赖标签质量 |
| 稀疏文本检索 | TF-IDF、BM25、学习稀疏表示 | 关键词、长尾词、精确概念 | 同义改写和跨模态较弱 |
| 稠密语义检索 | 文本或多模态 encoder + ANN | 同义表达、语义泛化、多模态 | 可解释性弱，可能语义漂移 |
| 混合检索 | 稀疏、稠密、属性结果融合 | 同时保留精确词和语义泛化 | 需要校准与配额治理 |
| 基于种子内容的 I2I | 用已看物品内容构造查询 | 无显式 query 的推荐场景 | 容易同质化和兴趣漂移 |

若内容 encoder 用用户反馈训练，它在模型结构上可能也是双塔；本章关注的是该通道依靠内容覆盖新品和语义意图的职责。

## 2. 查询与语料构造

查询可以来自显式搜索词、近期行为物品的标签聚合、用户长期兴趣词或场景上下文。物品文档由标题、类目、标签、品牌和内容理解结果组成，不同字段应设置权重。训练与评测时只能使用当时可见的物品内容版本，避免编辑后的文本泄漏。

内容特征需治理缺失、错标、同义词、语言、OOV 和标签作弊。多模态向量还要记录编码器与预处理版本，保证增量物品和存量索引在同一表示空间。

### 2.1 显式查询

搜索词、当前类目和筛选条件最接近传统信息检索。查询分析通常包括分词、拼写纠正、同义词扩展、实体识别和意图分类。价格、库存、地域等硬条件应作为过滤器，不应仅编码进向量后期待近似满足。

### 2.2 隐式查询

推荐场景没有搜索词时，可以从以下信号构造查询：

- 最近若干已看或正反馈物品的标题、标签和向量。
- 对短期行为按时间衰减聚合，对长期兴趣按主题分簇。
- 当前页面、入口、时间和设备等上下文。
- 用户明确关注的作者、品牌、类目或主题。

简单平均所有历史内容会混合互不相关的兴趣。更稳健的方法是保留多个兴趣 query，并为每个兴趣分配候选配额。

### 2.3 物品文档

文档可由标题、正文、类目路径、标签、品牌、作者、OCR、ASR、图像描述和结构化属性组成。字段要区分权重与可信度。例如商品型号应精确匹配，自动生成描述只能作为弱语义信号；用户可编辑标签需要防作弊。

## 3. 稀疏检索

### 3.1 倒排与 TF-IDF

倒排索引存储 `term -> postings`，适合类目、实体和关键词匹配。TF-IDF 提高稀有区分词的权重，但原始词频会偏爱长文档。

### 3.2 BM25

BM25 对查询词 $q$ 与文档 $d$ 的典型打分为：

$$
BM25(q,d)=\sum_{t\in q}IDF(t)\cdot
\frac{tf(t,d)(k_1+1)}{tf(t,d)+k_1(1-b+b|d|/avgdl)}
$$

$k_1$ 控制词频饱和，$b$ 控制长度归一化。多字段系统常采用 BM25F，对标题、类目和正文设置不同权重。稀疏检索特别适合型号、专有名词、长尾实体和必须命中关键词的请求。

## 4. 稠密与多模态检索

稠密检索用 encoder 将查询和物品映射到同一空间：

$$
s(q,i)=f_\theta(q)^\top g_\phi(i)
$$

训练样本可以来自点击、有效消费、同主题配对或人工相关标注；负样本应包括随机负例、同类难负例和模型近邻误召回。若仅用曝光点击训练，内容空间会逐渐吸收已有推荐策略的热门偏差。

多模态召回可采用：

- **早期融合**：先融合文本、图像、音频特征，再生成一个 item embedding。
- **后期融合**：各模态独立检索，再融合候选和分数。
- **跨模态检索**：文本 query 匹配图像/视频 embedding，或图像种子匹配文本商品。

早期融合服务简单但缺失模态处理困难；后期融合可单独治理每种模态，却增加索引和校准成本。

## 5. 混合检索与融合

稀疏和稠密通常并行。常见融合方式包括：

- 固定配额，各取一部分候选。
- Reciprocal Rank Fusion：$RRF(i)=\sum_m 1/(k+rank_m(i))$。
- 对 BM25、余弦分数分别校准后加权。
- 用轻量模型根据 query 类型动态分配权重。

精确型号 query 应提高稀疏和属性通道权重；自然语言描述、视觉风格或跨语言 query 更适合稠密通道。融合后必须去重，并保留命中的字段、词项或模态作为召回原因。

## 6. 新品与增量索引

新品发布后可直接从内容生成倒排项与 embedding，无需等待行为积累。完整链路包括：

1. 内容审核、字段标准化和结构化属性抽取。
2. 使用固定版本的 encoder 和预处理生成表示。
3. 写入倒排或 ANN 增量索引，并更新 catalog 资格。
4. 通过 shadow 查询检查召回可见性和近邻质量。
5. 累积反馈后逐步加入协同、I2I 和双塔主通道。

当 encoder 升级时，不能让新旧 embedding 长期混在同一空间。应全量重建、使用双索引切换，或通过经过验证的空间对齐完成迁移。

## 7. 在线服务

物品内容进入 Index 池后生成倒排项或 embedding；请求侧生成查询表示，执行检索、资格过滤和 Top-K。监控内容覆盖率、编码失败率、索引年龄、OOV 率、查询空结果率、相似度分布、新品覆盖、长尾覆盖和与协同通道的增量命中。

在线链路应先应用可下推的类目、语言、地域和库存过滤，避免检索大量无效候选；无法下推的规则在召回后过滤。过滤过重时应扩大检索深度或执行稀疏/稠密回退，防止最终候选不足。

内容 query 和 item embedding 可缓存，但缓存键必须包含 encoder、词典、语言和内容版本。对实时编辑内容要明确索引刷新 SLA。

## 8. 适用场景与局限

适合：新品与长尾、搜索式请求、明确类目/实体意图、多模态相似、跨域迁移，以及协同数据稀缺的早期系统。

局限：

- 内容相似不等于互补、购买意愿或长期满意度相似。
- 文本和标签可被操纵，自动内容理解也会产生错误。
- 稠密空间容易返回语义高度同质的结果。
- 用户隐式 query 可能混合多种兴趣并放大近期误触。
- 内容缺失或多语言不一致会造成系统性覆盖差异。

## 9. 评测与监控

评测除 Recall@K、NDCG@K 外，还应：

- 按新品/成熟、头部/长尾、显式/隐式 query 和语言分桶。
- 测量独占候选率、融合增量、L2 采用率和最终曝光率。
- 人工评估语义相关性、字段约束、安全性与重复内容。
- 监控内容覆盖、编码失败、索引年龄、OOV、空结果和相似度漂移。
- 追踪 encoder 版本切换前后的近邻变化与新品接入延迟。

只看点击会低估新供给，也可能奖励标题党。新品评测要使用时间切分，并确保目标时点的内容版本和 catalog 可见性正确。

## 10. 常见误区

- **内容召回只适合搜索**：推荐可从用户近期内容构造隐式 query。
- **稠密检索全面优于 BM25**：型号、实体和长尾关键词常由稀疏检索更稳定地处理。
- **新品有 embedding 就完成冷启动**：还需要进入正确人群、获得探索曝光并积累行为。
- **相似度高就是推荐价值高**：质量、价格、供给状态和用户效用仍需后续模型判断。
- **索引可原地混用不同 encoder**：表示空间不一致会使距离失去意义。
