# 其他召回方式

双塔、协同过滤、I2I 和生成式召回主要处理个性化相关性，但真实系统还必须应对无历史用户、新物品、突发热点、确定性业务供给和反馈不足等问题。本目录收录无法只靠个性化主模型稳定解决的补充召回通道。

这些通道按主要信号来源和业务职责划分，而不是按模型结构划分。例如内容召回可以使用双塔编码器，图召回也可以使用 ANN；将它们独立组织，是为了明确各自的数据生产、触发条件、候选责任和增量价值。整体关系见[其他召回方式综述](./其他召回方式综述.md)。

- [其他召回方式综述](./其他召回方式综述.md)：统一解释五类通道的分类依据、责任边界、服务架构、融合评测和组合方式。
- [热门与趋势召回](./热门与趋势召回/README.md)：区分累计热门、时间衰减、突发趋势、分群热门和新鲜供给，处理统计偏差、反作弊与流式更新。
- [内容检索召回](./内容检索召回/README.md)：覆盖属性倒排、TF-IDF/BM25、稠密与多模态检索、混合融合、新品索引和编码器迁移。
- [图与知识召回](./图与知识召回/README.md)：讲解一跳/多跳、PPR、Metapath 和图表示学习，以及异构关系、实体质量和扇出治理。
- [规则与运营召回](./规则与运营召回/README.md)：说明规则类型、配置模型、发布生命周期、冲突配额、审计安全和曝光兑现边界。

## 组织逻辑

五个子目录对应“时效信号、内容信号、关系信号、业务配置和不确定性”五种不同的信息来源。它们与个性化主召回并行运行，但不能使用同一套成功标准：热门通道关注时效和稳定性，内容通道关注冷启动覆盖，运营通道关注确定性约束，探索通道还必须记录曝光概率并控制试错成本。因此本目录按职责拆分，便于分别治理和评测。

## 按问题选择方法

| 当前问题 | 优先考虑 | 原因 |
| --- | --- | --- |
| 用户无历史或主模型故障 | 热门与趋势、规则兜底 | 不依赖完整个性化画像，服务稳定 |
| 新物品没有交互 | 内容检索、图与知识 | 利用上线即有的内容和实体关系 |
| 突发事件尚未进入训练数据 | 趋势召回、规则召回 | 更新速度快，可显式控制时效 |
| 用户表达了文本或标签意图 | 内容检索 | 查询与物品内容可直接匹配 |
| 候选依赖作者、社交或实体关系 | 图与知识 | 路径本身携带业务语义 |
| 活动、公共信息或协议供给必须入候选 | 规则与运营 | 结果确定、可审计、可回滚 |
| 新品因无曝光而长期无反馈 | 探索召回 | 受控分配机会并记录选择概率 |

真实系统通常组合使用。例如新品先由内容和知识关系进入相关人群的探索池，再由探索策略分配预算；获得稳定反馈后毕业到协同或主模型召回。通道之间应共享 Index 池资格，但分别保留召回原因、分数和版本，不能在去重后丢掉来源。

## 建议阅读顺序

1. 先读[其他召回方式综述](./其他召回方式综述.md)，建立职责分类和统一服务框架。
2. 阅读热门与内容召回，理解冷启动与时效性两类基础缺口。
3. 阅读图与知识召回，理解显式关系路径与协同相似的边界。
4. 阅读规则与运营召回，建立确定性配置、审批、审计和下游职责意识。
5. 最后阅读探索召回，把部分反馈、倾向概率和长期学习闭环串起来。
